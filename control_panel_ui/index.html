Providerها

وضعیت Runtime هر مقصد Web Chat.

ترافیک واقعی Web Chat

فقط درخواست‌هایی که به یک Provider انتخاب‌شده ارسال شده‌اند؛ Polling پنل و Health شمرده نمی‌شوند.

عملکرد Providerها در یک ساعت اخیر

درخواست، موفق/ناموفق، تأخیر، آخرین فعالیت و توکن اندازه‌گیری‌شده.

زنجیره آماده‌سازی Web Chat

۱. Browser Profileمرز داده مرورگر و Storage
۲. Browser RuntimeChrome/CDP و Tabهای Provider
۳. Account / LoginSession و هویت Account Instance
۴. Provider Profileقرارداد منطقی Provider/Account
۵. Discovery & Readinessکاوش، گواهی و READY عملکردی

Runtimeهای مرورگر

عملیات Start / Open فقط اینجا انجام می‌شود. Provider صفحه مدیریت منطقی است، نه کنترل Browser.

پروفایل‌های مرورگر و مرز ذخیره‌سازی

Profile محل داده مرورگر است؛ وضعیت sharing باید همراه Origin و Account تفسیر شود. Cross-origin sharing می‌تواند ایزوله باشد، اما same-origin multi-account در یک Profile مجاز نیست.

Browser Profiles

Accountهای متصل و حالت isolation از NG Inventory خوانده می‌شوند.

Account Instances و Session Lifecycle

واحد Login و Session، Account Instance است. هر کارت رابطه Provider Profile → Account → Browser Profile/Origin → Runtime → Session → Readiness را نشان می‌دهد.

پراوایدرهای ثبت‌شده

این صفحه فقط تنظیمات منطقی Provider را مدیریت می‌کند. Browser/Profile در «مرورگر و اتصال» مدیریت می‌شود.

Provider یک قرارداد منطقی است. Browser Runtime و Account در Workspaceهای خودشان مدیریت می‌شوند؛ اینجا مدل، Feature defaults، وضعیت فعال‌سازی و Readiness دیده می‌شود.

افزودن Provider

Provider را تعریف کنید، سپس آن را به یک Browser Runtime موجود متصل کنید. فعال‌سازی عملیاتی بعد از Login/Discovery/Certification انجام می‌شود.

۱

تعریف Provider

Provider جدید همیشه غیرفعال ثبت می‌شود. فعال‌سازی فقط پس از Login، Discovery و Certification انجام می‌شود.
۲

اتصال به Browser Runtime

CDP و Profile به‌صورت دستی وارد نمی‌شوند؛ از Runtime انتخاب‌شده خوانده می‌شوند تا رابطه Browser/Profile ناسازگار ایجاد نشود.

۳

مرور و ثبت

نوع Provider و Browser Runtime را انتخاب کنید.
این فرم فقط Provider Definition را می‌سازد. Account Instance هنوز ایجاد نمی‌شود. مسیر بعد: Provider غیرفعال → Accounts (ساخت/انتخاب Account) → Login/Session → Discovery → Functional Readiness → Enable.

مدل‌ها و قابلیت‌ها

ماتریس کامل قابلیت هر پراوایدر از Runtime API + فهرست مدل‌ها از /v1/models.

دامنه گواهی و Evidence

قابلیت اعلام‌شده با آمادگی گواهی‌شده یکی نیست. این بخش Account/Model/سن Evidence را از Readiness record نشان می‌دهد.

قابلیت‌های Runtime

کاوش و گواهی

Research-first → Baseline → Deterministic Exploration → Behavior Lab / AI-assisted analysis when needed → Synthesis → Update Candidate → Automated E2 or Human Acceptance. هیچ Run جدیدی مستقیم به Profile عملیاتی اعمال نمی‌شود.

Discovery Engine 2.x

نقشه اجرای Discovery

۱. Researchمنبع رسمی/داخلی/پروژه بالغ؛ قبل از هر کاوش
۲. BaselineRuntime، Page، Account و وضعیت دسترسی
۳. ExplorationDOM/Accessibility/Network با Probeهای deterministic
۴. Assisted InvestigationBehavior Lab و در صورت نیاز AI با Policy/Provenance
۵. Synthesis & CandidateDrift به Update Candidate تبدیل می‌شود؛ patch پنهان ممنوع
۶. CertificationAutomated E2 فنی یا Human Acceptance؛ دو مسیر مستقل
اگر Login، Verification/CAPTCHA، Block یا وضعیت نامشخص تشخیص داده شود، Exploration متوقف و پس از رفع شرط Baseline دوباره اجرا می‌شود.

ایجاد Run فقط state اولیه RESEARCH_REQUIRED را می‌سازد. Research-first gate قابل دور زدن نیست.

Runهای ثبت‌شده

State، Evidence، Account و تاریخچه هر Run از رکورد نسخه‌دار خوانده می‌شود.
